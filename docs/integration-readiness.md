## 2. 클라이언트 현재 상태

### 프런트엔드

- `frontend/package.json`, 잠금 파일과 React·TypeScript 소스가 존재한다.
- 이번에 실행한 `develop@9e462a8`에는 로그인·회원가입·대시보드·세션·리포트·프로필 화면이 구현돼 있다. 공통 API 클라이언트는 Bearer 헤더·Refresh 쿠키·401 단일 갱신과 오류 문구를 처리한다.
- 프로필·프라이버시의 현재 API 필드와 enum은 백엔드와 일치한다. 리포트는 null·분/시간/일/주 타임라인을 구분한다.
- 세션 화면은 임의 점수를 1분마다 v1으로 전송한다. 실제 AI 측정값을 화면에 연결한 상태가 아니다.
- 원격 `origin/main@40bc369`에는 피드·랭킹·친구·그룹 목록·상세, 학습 시간 공개 편집, Refresh 장애 시 로그인 유지, 리포트 페이지·공유·PDF 인쇄가 이미 추가됐다. 현재 작업 트리와 프런트 19개 파일이 다르며 다음 단계는 이 기존 기능의 동기화·연결 검증이다.
- 프런트 잠금 의존성 설치 후 build·lint와 격리 API 109개 요청이 통과했다. 실제 브라우저는 localhost 로그인→dashboard 이동까지만 확인했으며 쿠키 재발급·화면 종합 검증은 미완료다. 세부 범위·환경 제약은 [프런트 인계](frontend-handoff.md)에 기록한다.

### AI

기존 AI 프로그램:

- Python·OpenCV·MediaPipe 웹캠 실행과 약 10 FPS 추론
- 얼굴 검출, gaze 상대 위치, 단일 프레임 눈 감김, yaw/pitch/roll 추출
- 백엔드와 같은 `total` 계산 함수
- JWT Bearer 집중도 로그 API 클라이언트
- 디버그 화면과 프레임별 JSON 출력

별도 백엔드 연결 도구에서 완료:

- AI-2의 3초 gaze/head 보정, blink·장시간 눈 감김 판정과 1분 집계
- AI-3의 SQLite 영속 큐, 같은 ID·측정 시각 재전송, Refresh 회전과 키체인 저장
- LBE-4 `local:ai`의 일반 로컬 로그인·세션·연속 카메라 측정·재개·종료
- 실제 카메라 2분에서 99.23점·98.81점, 리포트 평균 99.02점 확인
- 전송 중단·응답 유실 후 두 번의 프로세스 재시작으로 중복 없이 2행 복구

Python 3.11에서 검증했다. 기존 `focuslens-ai` 프레임 측정 명령과 프런트 기능은 유지한다. 실측의 세션·리포트 ID와 증거 경로는 [LBE-4 완료 기록](backend-plan.md#lbe-4-완료-기록-2026-11-26)을 따른다. 실제 AI 점수·상태를 프런트의 세션·알림 화면에 연결하는 작업은 남아 있다.

## 3. 확정된 계약과 로컬 인계

다음 계약은 확정했으며 기존 v1 호환을 유지한다.

| 작업 | 상태 | 결과물 |
| --- | --- | --- |
| 로그 v2 필요 여부 결정 | ✅ | `docs/client-contract-decisions.md` |
| 장시간 세션 인증 결정 | ✅ | 회전형 Refresh Token 정책 |
| AI 재시도 기준 결정 | ✅ | 상태 코드별 처리와 backoff 규칙 |
| AI 인수 기준 작성 | ✅ | 보정·blink·미검출·1분 집계 최소 기준 |
| 프런트 API 매핑 작성 | ✅ | `docs/frontend-api-map.md` |
| 제품 E2E 시나리오 확정 | ✅ | `docs/product-e2e-scenarios.md` |

위 여섯 항목은 문서 계약으로 확정했다. 현행 v1 로그를 유지하면서 로그 v2와 Refresh Token 백엔드 구현 및 fixture·실제 HTTP 통합 검증도 완료했다.

LBE-1~4에서는 새 로컬 기동, 기존 데이터 보존·백업·복원, DB·Redis 장애 복구·종료, 일반 서버에서 지속 AI 연결을 검증했다. LBE-5는 같은 주소·계정·명령으로 프런트 팀이 API를 사용할 수 있도록 CORS·쿠키·다중 계정·그룹 권한·공개 범위를 인계한다. 실행 절차와 현재 UI 경계는 [프런트 인계](frontend-handoff.md)를 기준으로 한다.

## 6. Phase 5 제외 진행 순서

1. [✅] 로그 v2·Refresh Token 백엔드 구현과 fixture·HTTP 통합 테스트
2. [✅] AI-1~3 보정·집계·영속 전송과 LBE-4 일반 서버 실제 카메라 E2E
3. [✅] 제품 프런트엔드 소스와 핵심 화면 확보
4. [✅] LBE-5 로컬 프런트 인계의 API·빌드·로그인 확인과 미완료 브라우저 범위 기록
5. 최신 main 프런트 동기화·기존 화면 API 검증 후 실제 AI 화면 연결
6. AI·프런트·백엔드를 연결한 전체 사용자 흐름, 출력 보안·반응형·접근성 검증

LBE-5는 백엔드 인계 단위이며, 전체 제품 통합의 완료 선언은 아니다. AWS 배포와 외부 HTTPS·클라우드 인프라는 사용자 요청에 따라 계속 보류한다.
