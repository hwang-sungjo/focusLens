## 실행 순서

1. 각 실행은 격리된 테스트 사용자와 세션을 생성한다.
2. API 응답, DB 결과, 화면 표시를 같은 request ID와 resource ID로 연결한다.
3. 실패 시 민감값을 제외한 요청 경로·상태·request ID를 증거로 남긴다.
4. AI-2·3과 LBE-4에서 카메라 집계, 영속 큐 재전송, 인증 갱신을 검증했다. FE-3에서 이 경로를 제품 세션 화면에 연결했다. FE-4에서 실제 여러 분 측정 중 전송 단절·복구까지 재현한다.
5. FE-2의 `npm run verify:fe2`는 가입·로그인·로그아웃, 세션 리포트, 필드별 공개 범위, 친구 요청·수락, 그룹 역할, 랭킹 점수, Refresh 503 안내·재시도를 브라우저에서 확인한다. 점수는 99.23점 실측 집계 재생값과 0점 테스트값을 사용한다. [FE-2 검증 범위](frontend-handoff.md)
6. 월말·Roll-up, 장시간 세션, 출력 보안 등 표의 나머지 조건은 각각의 시나리오로 검증한다.

## 완료 판정

- 모든 필수 시나리오가 동일 릴리스 후보에서 통과한다.
- 401·403·409·503이 정의된 UX로 표시된다.
- 점수·시간·프라이버시·역할 결과가 API와 화면에서 일치한다.
- 테스트 중 토큰, 비밀번호, DB·Redis URL이 로그와 화면에 노출되지 않는다.
